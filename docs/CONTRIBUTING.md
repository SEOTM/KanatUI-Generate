# 贡献指南

## 1. 范围

欢迎的贡献：缺陷修复、文档订正、控件库的绘制改进、几何与事件契约的补全、构建与运行问题的报告。

改动前请先确认属于哪一层：

- `src/framework/` 是框架层，不出现"文档""编辑器""保存"这类应用语义；
- `src/doc/`、`src/editor/`、`src/app/` 是应用层，可以引用框架的公开接口，框架不得反向依赖它们；
- 文档里的字段名、控件类型串与 bin 记录布局属于对外契约，改它们要单独说明兼容性。

## 2. 编码风格

- 缩进用制表符；大括号另起一行（Allman）。
- 类型名 PascalCase（`LayoutModel`、`CtrlInfo`）；函数名 PascalCase（`BuildLayoutFromEntry`）；常量与宏全大写加下划线（`BIN_VERSION`、`CTRL_MAX`）。
- 变量带类型前缀：`p` 指针、`pp` 二级指针、`pfn` 函数指针、`b` 布尔、`n` 有符号整数、`dw` 无符号整数、`qw` 大小、`sz` 字符串、`lp` 长指针、`cr` 颜色。
- 成员变量不加 `m_` 前缀；静态成员与普通成员靠上下文区分。
- 不使用 `new` / `delete`；对象经分配器（`Arena` / `MemPool` / `AllocatorHub`）分配。
- 不使用异常、RTTI 与虚函数；跨层解耦用函数指针表。
- 失败返回 `BOOL`（`TRUE` / `FALSE`），不弹窗、不抛异常；诊断走 `printf`。

## 3. 注释约定

- 每个源文件开头是一段 `// ====` 分隔的说明块，写文件职责、边界与关键不变量。
- 每个函数上方写两行以上：`// 函数: <名字>` 与 `// 描述: <一句话职责>`；参数、返回值、注意事项按需追加 `// 参数:`、`// 返回:`、`// 说明:`。
- 分区用 `// 区域: <名字>`；结构体字段用行尾 `//` 注释。
- 注释内容是纯文本：不使用 emoji，不使用 Markdown 记号（加粗、反引号、列表符号）；强调靠措辞与分节。
- 注释写"为什么"和"约束"，不复述代码；契约细节优先写进同目录的 `.md` 接口文档，代码只留摘要与指针。

## 4. 文档

- `src/` 下每个模块（一组 `.h` / `.cpp`）配一份同名 `.md`，写当前接口、契约、用法与失败语义；体例见 [INTERFACE-DOC-STYLE.md](INTERFACE-DOC-STYLE.md)。
- 接口文档随代码同轮更新；改了函数签名、失败条件或数据布局，必须同步对应 `.md`。
- `docs/` 下的工程文档（架构、构建、格式、派生）只在"对外行为改变"时更新，不在里面记录临时过程。

## 5. 构建与自检

提交前至少：

1. Release 与 Debug 两种配置均 0 警告 0 错误；
2. 无人值守启动一次，退出码 0（`KANATUI_GENERATE_AUTOCLOSE_MS`）；
3. 加载链命中的级别与预期一致；
4. 改动涉及保存或加载时，做一次"载入 → 另存 → 再载入"的往返，确认文档内容不漂移；
5. 改动涉及几何时，在两种窗口尺寸下目视核对目标控件的位置与尺寸。

## 6. 提交与合并请求

- 一条提交做一件事；标题用"范围: 动作"的形式，例如"geometry: 修正负系数下的宽度解算"。
- 提交正文写清动机、改动面、自检结论；涉及契约变更时列出受影响的字段或函数。
- 不提交构建产物、依赖缓存、临时文件与个人草稿（`.gitignore` 已覆盖）。
- 合并请求请说明改动属于哪一层、是否改动对外契约、如何验证。

## 7. 新增模块清单

新增一个模块时：

1. 在对应层建 `.h` / `.cpp`；
2. 在 `docs/INTERFACE-DOC-STYLE.md` 的体例下写同名 `.md`；
3. 在父模块的接口文档里登记依赖关系；
4. 在工程源文件清单里加入 `.cpp`（发布树不含构建定义，使用者自建工程时需要自己加）；
5. 若新增控件类型，按 [DERIVE.md](DERIVE.md) 第 3 节同步类型表、层次步进、缓冲容量与绘制分派。
