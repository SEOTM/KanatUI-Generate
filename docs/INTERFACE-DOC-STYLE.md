# GenUI · 接口文档体例

> 本文件是 GenUI 工程接口文档的体例判据。所有 `src\` 下的接口文档按本文件书写;
> 体例本身不随单个模块调整, 需要改体例时先改本文件、再批量回改文档。
>
> 形态来源: 概述部分参考 Windows API 头文件页(简短介绍 + "本模块包含以下编程接口" +
> 按类别分组、逐项一句说明的表格), 函数接口部分参考 Windows API 函数页(摘要 / 语法 / 参数 /
> 返回值 / 注解); 其中"要求"在本文档体系里提为模块级一节(`## 要求`, 同一文件的接口共用一套值,
> 不逐条重复)。参考页中的"另请参阅"等跳转链接不抄 —— 本文档体系内不出现任何超链接。
>
> **公开版说明**: 本仓库为公开版本, 已移除逐轮过程留痕(`docs\HISTORY.md`、`docs\archive\` 等)与内部工程管理文档。
> 源码与接口文档中指向这些文件的引用仅用于说明沿革。
>
> 体例来源 = `Kanat` 工程 `docs\INTERFACE-DOC-STYLE.md`(该工程第 26 轮树立、第 27 轮推广到 29 份);
> GenUI 采纳同一体例并全仓统一, 与 `Kanat` 侧保持可对照。

---

## 1. 文件粒度

- 一个源文件模块 = 一份文档: `.h` / `.cpp` 成对的模块写成一份 `<模块名>.md`, 与源文件同目录
  (例: `src\framework\GeometrySolver.h` + `src\framework\GeometrySolver.cpp` ⇒
  `src\framework\GeometrySolver.md`)。
- 单文件模块同样各成一份: `src\main.cpp` ⇒ `src\main.md`。
- 纯常量头(只有一个公开常量集合、无函数与类型的)并入其唯一使用方的模块文档, 不单独立份;
  需要单列时在概述末句一句话交代。
- 文档覆盖该模块对外公开面: 命名空间内声明的函数、公开类型、公开常量/枚举值。文件内 `static`
  函数、匿名命名空间内容、只在本编译单元生效的内部件不立条, 必要时在概述末句一句话交代。
- 文档不替代 `README.md` / `docs\PLAN.md` / `docs\STATUS.md` / `docs\HISTORY.md`: 沿革、轮次、
  复核状态、使用方清单一律不进接口文档(这些属现行工程文档与历史留档)。

## 2. 文档结构

```markdown
# <模块名> 模块 (<相对路径>)

## 概述

<模块定位与边界: 做什么 / 不做什么 / 层归属 / 依赖方向, 3-6 行>

本模块包含以下编程接口:

### 函数

| 函数 | 说明 |
| --- | --- |
| `FuncA` | 一句话说明(动词开头, 与函数节摘要同粒度)。 |

### 类型

| 类型 | 说明 |
| --- | --- |
| `TypeA` | 一句话说明。 |

### 常量

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `CONST_A` | `0` | 一句话说明。 |

---

## FuncA 函数 (<命名空间或模块>)

<一句话摘要>

### 语法

```cpp
RET FuncA(
  [in]  TYPE1 a,
  [out] TYPE2* b
);
```

### 参数

`[in] a`

类型: **TYPE1**

参数说明。

`[out] b`

类型: **TYPE2\***

参数说明(含失败时的取值约定)。

### 返回值

类型: **RET**

返回说明; 无返回值写"此函数不返回值"。

### 注解

前置条件 / 失败口径 / 副作用 / 所有权 / 时序 / 线程与平台限制。
```

接口节不含"要求": 标头 / 实现 / 命名空间 / 依赖 / 平台 / 线程安全是模块级信息, 同一文件的多个
接口共用同一套值 ⇒ 整份文档只写一次, 放在文档末尾的 `## 要求` 节(见下), 不在每个函数 / 类型 /
类 / 常量节里重复。

类型节沿用同一骨架: `## <类型名> 结构/枚举 (<命名空间>)` + `### 语法` + `### 成员`
(逐成员一段, 字段表或引用块) + `### 注解`。

常量节骨架(带成组契约、需要逐条注解的常量; 纯常量模块仍按 §3 第 8 条只在概述表列出):

```markdown
## <常量名或前缀组> 常量 (<命名空间>)

<一句话说明>

### 语法

```cpp
constexpr DWORD <常量名> = <值>;
```

### 值

<取值原文; 由运行期决定的写"运行期取值"并给出来源>

### 注解

<阈值语义、位或关系、与其它常量的成对契约、谁消费它>
```

常量无"参数"与"返回"两节: 参数为空是噪音, 返回值语义即"值", 合并进"值"节。

模块级要求节(每份文档一个, 放在文档末尾; 纯常量模块可紧接概述):

```markdown
## 要求

| 要求 | 值 |
| --- | --- |
| 标头 | `<包含路径>`(`src\<相对路径>`) |
| 实现 | `src\<相对路径>`; 纯头文件写"无(纯头文件)" |
| 命名空间 | 模块命名空间 / 全局 / 类名 |
| 依赖 | 工程内模块 + 链接库与系统 DLL(不适用写"无") |
| 平台 | 适用的 Windows 版本与前提 |
| 线程安全 | 是 / 否(并写约束) |
```

依赖行写整个模块的依赖并集; 单个接口的特例(如只有某函数需要的库、只读接口可并发)写在该节的
"注解"里, 不在要求表里逐条区分。

类节骨架(有公开方法的模块, 如 `MemoryManager` / `D3D11Manager`):

````markdown
## <类名> 类 (<模块>)

<一句话定位>

### 语法

```cpp
class <类名>
{
public:
    <类名>(<构造参数>);
    ~<类名>();
    RET Method(<参数>);
    ...
};
```

### 成员

| 成员 | 说明 |
| --- | --- |
| `<类名>(<参数>)` | 构造语义与建立时机。 |
| `~<类名>()` | 析构语义(是否释放 / 是否清零)。 |
| `Method(<参数>)` | 一句话说明(契约复杂时在注解里按成员展开)。 |
| `CONST_NAME` | 公开常量及其阈值语义。 |

### 注解

按成员分条写共同契约之外的内容: 失败口径、所有权、调用顺序、线程约束。
````

## 3. 各节写法

1. **概述**: 只写当前成立的定位与边界。函数 / 类型 / 常量表必须列全公开面, 说明列一句(允许带
   失败口径一类的关键限定, 不展开成长段)。
2. **摘要**: 一句, 动词开头; 与表格里的说明不重复长句。
3. **语法**: 照抄头文件声明(可整理缩进与对齐); 参数按方向标注 `[in]` / `[out]` / `[in, out]`;
   有默认参数时写出默认值; 函数指针 / 回调类型写到可读即可。
4. **参数**: 逐参数一段, 第一行为 `[方向] 参数名`, 其后"类型: **类型名**", 再其后说明。
   参数说明必须交代: 取值范围或合法域、为空/越界时的处置、以及是否被写回(OUT 参数失败时是否改动)。
5. **返回值**: 先写"类型: **类型名**", 再写取值语义(成功 / 失败的返回值、失败判定方式)。
   无返回值写"此函数不返回值"。
6. **注解**: 写调用方需要知道但语法与参数表放不下的内容 —— 调用时机、前置条件、失败回退路径、
   资源所有权转移、与其它接口的先后约束、平台差异。不写实现步骤流水账, 只写对外可见的契约。
7. **模块级要求**: 每份文档末尾一个 `## 要求` 节, 固定六行(标头 / 实现 / 命名空间 / 依赖 / 平台 /
   线程安全); 不适用的行写"无"。接口节内不写要求表 —— 同一文件的接口共用同一套要求, 重复 N 次
   没有信息量。依赖行写模块级并集(链接库与 DLL 名); 平台行写最低版本与前提(例: DWM 属性不可用时
   走区域裁剪回退); 单接口特例写在该节"注解"里。
8. **常量**: 值确定的写值; 由运行期决定的写"运行期取值"并给出来源。常量若带成对契约(如"事件名 ↔
   文档字段"), 在说明列写清成对关系。
9. **类**: 每个类一节, 不把类里的方法拆成独立函数节。语法块给出公开面骨架(构造 / 析构 / 公开方法 /
   公开常量); 成员表逐条一句话; 注解按成员分条展开契约(失败口径 / 所有权 / 调用顺序 / 线程约束)。

## 4. 不写什么

- 不写沿革(第 N 轮、谁提出、旧实现)、不写复核状态(探针、日志、基线)、不写"使用方"表
  (框架模块尤其不得把使用方写成某个具体应用层模块)。
- 不写超链接、不写"另请参阅"列表; 跨模块引用一律写标识符本身(反引号包裹), 需要时补一句纯文本
  出处, 例: "参数形态见 `ControlSpec.h` 的 `PackWndPos`"。
- 不写代码注释里已有的结构性说明(文件头横幅、区域划分), 也不复述代码逐行行为。
- 不写 emoji, 不写 markdown 行内强调以外的装饰记号; 强调靠措辞与分节。

## 5. 与代码注释的关系

- 代码侧注释形态由注释治理批次另行约定, 本文件不规定注释格式; 接口语义以本文档为唯一真源。
- 代码注释与本文档冲突时, 以代码实际行为为准, **先改文档、再改注释**, 并在当轮留痕中记一句。

## 6. 工具与校验

- 文档为 UTF-8(无 BOM) + LF 纯文本; 中文正文的标点沿用本仓既有惯例 —— 逗号、冒号与括号用半角,
  分号与中文引号用全角; 代码与标识符用半角。同一份文档内不得混用两套逗号/冒号/括号。
- 每份文档收尾自检四项: ①概述索引表与正文条目一一对应 —— 每个正文节都有一个索引条目, 索引条目
  也都要落到某个正文节(仅在概述表列出、不立节的纯常量按 §3 第 8 条处理, 不计入正文节数, 但必须
  在概述表列全); ②每个条目都有完整节骨架 —— 函数节 = 语法 / 参数(无参可省) / 返回值 / 注解,
  常量节 = 语法 / 值 / 注解, 类与结构节 = 语法 / 成员 / 注解; ③全文无 `](` 形式的超链接;
  ④每份文档**有且只有一个** `## 要求` 节(模块级六行), 接口节内不得再出现 `### 要求`。
- 覆盖自检: `src\` 下每个模块(`.h` / `.cpp`)都在其 `.md` 中至少有一条索引记录, 或在该 `.md` 的
  概述里以一句"内部件不立条"交代。
