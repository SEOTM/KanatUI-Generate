# 架构

## 1. 定位与边界

Kanat UI Generate 是一个 Windows 原生的声明式界面框架，以及一个用该框架自身实现的界面设计器。界面结构由布局文档（JSON 或二进制 `.bin`）描述，代码里不写死界面；设计器负责增删控件、调整几何、打开与保存文档，预览窗口实时呈现被编辑的布局。

边界：

- **框架层不含编辑器语义**。`src/framework/` 不知道"文档""设计器""保存"这些概念，可以整体迁移到其它项目复用。
- **布局文档是唯一真源**。控件的类型、标签、文本、事件与四轴几何系数都来自文档；运行期不提供用代码拼界面的回退路径。
- **渲染只经能力表**。布局层与调度层不包含任何具体 UI 库的类型；渲染后端通过函数指针表注入，替换 UI 技术时不改布局代码。
- **只有 Windows x64**。图形后端目前只有 ImGui + D3D11；未启用 ImGui viewports。

## 2. 分层与依赖方向

```text
app\            应用层:双窗口宿主、应用主类、启动加载链、文档 I/O、预览会话、内嵌成员
  ├─ editor\    编辑器层:外壳逻辑、编辑命令、写方向序列化、选中态叠加件
  │    └─ doc\  文档领域层:文档承载者、结构一致性校验、数据保真旁挂表
  └────────────> framework\   框架层(可迁移复用,不含编辑器语义)
                   ├─ base\       设计参考量、控件类型契约、控件缓冲、文本宽度、分配器、校验
                   ├─ render\     渲染能力接口(RenderApi / CtrlApi / HostApi)与 ImGui 实现
                   ├─ layout\     布局对象、中间态、解析、几何解算、渲染出口
                   └─ dispatch\   帧间事件、事件绑定表、调度与场景切片、资源与路径
```

依赖方向是单向的：`app → editor → doc → framework`。框架层不反向依赖任何上层；`doc` 只调用 `framework` 的公开接口。

`framework/dispatch` 随框架一并就位（调度层、场景装配、帧间事件、事件绑定、资源路径），但本工程的宿主生命周期由 `app/AppHost` 驱动：双窗口、编辑器协调与预览会话都不走单文档调度层的整条流程。`Dispatch` / `DispatchScene` 两件参与框架契约与事件绑定，不参与运行时接线。

## 3. 启动与数据流

### 3.1 启动加载链

`app/DocumentSource` 按固定级序探测可用文档源，命中即用，不再探测后续级别：

| 级别 | 来源 | 形态 |
| :--- | :--- | :--- |
| 1 | exe 目录 `.\KanatUIGenerate.bin`（外部文件） | bin |
| 2 | exe 目录 `.\KanatUIGenerate.json`（外部文件） | JSON |
| 3 | 内置资源 `resource.res\KanatUIGenerate.bin` | bin |
| 4 | 内置资源 `resource.res\KanatUIGenerate.json` | JSON |

形态由内容嗅探判定，与扩展名无关；四级全未命中或全部载入被拒时启动中止，不内置代码回退。未内嵌资源时，把示例文档放到 exe 同目录即可命中第 2 级。

### 3.2 初始化顺序

```text
main.cpp
  └─ AppHost::Run
       ├─ 打开 DPI 感知
       ├─ Application::Init
       │    ├─ 建立内存池与会话分配器
       │    ├─ 分配成员存储
       │    ├─ 注入文档承载者 / 旁挂表反查 / 会话回调
       │    ├─ 启动加载链载入文档 → 中间态
       │    ├─ 逐布局构建文档条目(链式布局对象 + 参考尺寸 + 元信息)
       │    ├─ 解析保留名 KanatUIGenerateEditor 的外壳布局为只读快照
       │    └─ 由外壳源装配内嵌(flex)窗口成员
       ├─ 建两个标准窗口(编辑窗口 + 预览窗口),建立 ImGui / D3D11 面
       ├─ 注入事件绑定表、命令层回调、宿主能力
       ├─ KanatUIGenerateEditor::Init(注册控件选中回调、校验外壳锚点)
       └─ 运行主循环:每帧一次 FrameOnce
```

### 3.3 数据流

```text
布局文档(JSON / bin)
  └─ LayoutSolver ──> FileMidState(中间态:布局链 + 元素链)
        └─ BuildLayoutFromNode ──> Layout(布局对象) + CtrlBuffer(控件缓冲)
              └─ LayoutRender ──> RenderApi / CtrlApi ──> ImGui ──> D3D11

编辑器改动 ──> 中间态(元素规格 / 布局信息) ──> 预览同步 ──> 布局对象像素几何
编辑器保存 ──> LayoutWriter ──> JSON / bin
```

中间态是编辑与保存的共同真源：编辑改的是中间态里的元素规格与布局信息，布局对象只是"按当前参考尺寸解算出来的像素视图"。

## 4. 文档模型

一份文档是 `layouts` 数组，装载为 `FileMidState`：

| 结构 | 内容 |
| :--- | :--- |
| `LayoutNode` | 一份布局：`LayoutInfo`（名称、标签、参考尺寸、窗口尺寸系数、可最大化 / 可缩放、窗口位置）+ 元素链 |
| `ElementNode` / `ElementSpec` | 一枚控件：标签、文本、类型串、事件名、四轴 `SizeFactor`（8 系数 + 像素偏移）、ID、父容器 ID |

`doc/Document` 是文档承载者，按值内嵌在应用成员块内：

- `LayoutEntry[]`：每个布局条目一份，含参考尺寸 `AutoSize`、经验参数 `RefSize`、名称、窗口几何、中间态节点指针。布局对象不按条目各留一份——全部条目共享同一个"唯一预览基座"（见第 10 节）。
- `FileMidState`：中间态本体。
- 关联磁盘路径与"未保存改动"标记。

`doc/RawAttributes` 是两张按文档索引键的旁挂表，保存"原类型串"与"无缓冲控件的声明文本"。作用是把文档里不认识或不能由控件缓冲承载的内容原样保留，保存回写时不丢失。表惰性建立、只增不减，删除控件时条目整体前移。

## 5. 布局对象

`framework/layout/Layout` 是运行时布局对象，两种存储模式在创建时确定：

| 模式 | 用途 | 能力 |
| :--- | :--- | :--- |
| 线性数组 | 只读展开态（外壳快照、内嵌成员） | 按索引取控件，不做增删 |
| 双向链 | 可编辑布局（预览基座） | 按索引插入 / 删除 / 重排，O(1) 尾插；编辑器的增删控件就落在这里 |

控件信息 `CtrlInfo`（80 字节）持有像素几何、标签、类型、ID、父容器 ID、控件层次与控件缓冲句柄；几何系数不在控件里，而在中间态的 `ElementSpec` 中。结构件 `WND` / `TITLE` / `CNTR` 固定占布局的前三个槽位。

## 6. 几何模型

### 6.1 参考量

八个参考量依次为屏幕宽、屏幕高、窗口宽、窗口高、控件高、字号、间隔、内边距。前两项取自主显示器；后六项由布局的 `autosize` 经验参数推导：

```text
参考量像素 = 千分比 × 换算基准 / 1000
```

换算基准由 `mode` 决定（屏宽 / 屏高 / 窗宽 / 窗高），缺省为屏高。窗口宽高在窗口建好后取实际客户区。

### 6.2 像素解算

```text
像素值 = Σ(coeff[i] × 参考量[i]) + offset     (i = 0..7)
```

四轴（x / y / width / height）各有一组 8 系数与一个整数偏移，整式实现在 `GeometrySolver::FactorAbsPx`。布局窗口尺寸由布局级 `width` / `height` 按同一公式解算；窗口桌面位置取 `WND` 件的 x / y，越屏或越界时按宿主工作区降级。

### 6.3 层次与层号

`CtrlInfo::nLayer` 由父容器 ID 链递推：`域`（矩形、输入、列表、下拉、渲染面、滑动条）每嵌套一层下沉一档，`件`（按钮、复选框）上浮一档，其余继承父层。结构件恒为 0。绘制层号 = 背景层号 + 层次，钳制在 1..16；配色由一条"底色端 → 光色端"的单调色轴按层号取样，亮暗模式通过采样方向切换。

## 7. 渲染抽象

`framework/render/Render.h` 定义三张函数指针表，表内只用框架自有语汇（像素坐标、控件结构、样式槽）：

| 表 | 提供方 | 消费方 | 内容 |
| :--- | :--- | :--- | :--- |
| `RenderApi` | ImGui 实现（`ImGuiRender`） | 布局渲染出口 | 取得 / 开合窗口与容器、光标、ID 命名空间、命中判定、绘制量统计（16 项） |
| `CtrlApi` | 控件库（`Controls::GetCtrlApi`） | 布局渲染出口 | 控件上下文、逐控件绘制、活动输入查询（3 项） |
| `HostApi` | 宿主（`ImGuiHost` / `AppHost`） | 调度与场景层 | 窗口生命周期、帧循环、样式、可见性、窗口矩形、自证统计 |

布局渲染出口 `LayoutRender` 有三个入口：`RenderBase`（整个基座布局）、`RenderPreviewBase`（基座 + 内容控件逐枚点击判定 + 视图叠加件）、`RenderFlex`（无独立窗口句柄的内嵌布局）。三者都不认识窗口句柄——渲染目标由 `RenderApi::AcquireWnd` 决定。

ImGui 侧的分工：

- `ImGuiHost`：窗口类、消息循环、context、帧流程、段结算、IME 开关、样式落地。
- `D3D11Manager`：设备、交换链、渲染目标。
- `ImGuiRender`：`RenderApi` 的唯一填表处。
- `Controls` / `Widgets`：控件绘制与部件层，提供 `CtrlApi`。

## 8. 控件与部件

控件类型表共 22 种（不含 `INVALID` / `UNKNOWN` 两个非控件哨兵）：

| 分组 | 类型 |
| :--- | :--- |
| 结构件 | `WND`、`TITLE`、`CNTR` |
| 文字与图形 | `TEXT`、`RECT`、`RENDER` |
| 输入 | `INPUT_SINGLE`、`INPUT_MULTI`、`INPUT_NUMERIC`、`INPUT_REAL`、`INPUT_ACTION` |
| 选择 | `BUTTON`、`CHECKBOX`、`SLIDER`、`COMBO`、`COMBO_ACTION`、`PROG`、`TIMEBAR` |
| 列表 | `LIST`、`LIST_INPUT`、`LIST_COMBO`、`LIST_TIMESPAN` |

其中 18 种有绘制实现；`WND` / `CNTR` 是结构件，由渲染出口开合窗口与内容容器，`LIST` / `LIST_TIMESPAN` 在类型表中但暂无绘制实现（按未知类型占位）。类型串由文档给出，未命中即 `UNKNOWN`，按矩形占位绘制。

控件缓冲 `CtrlBuffer` 承载控件状态：文本类存 C 字符串并按类型给容量；列表类存 `ListBuffer` 头 + 行数据区；下拉与输入动作有各自的结构。绘制是缓冲的函数，事件只经回调函数执行。

部件层 `Widgets` 是"由多个图元拼成、可复用"的绘制单元（输入动作、下拉动作、时间条、列表行等），控件库按类型调用部件，再由部件落到 `RenderApi` 的基本图元。

## 9. 事件模型

文档的 `event` 字段是事件名。装配期由事件绑定表把名字解析为 `pfnCtrlEvent`：

```text
pfnCtrlEvent(obj, oper, param, data)
```

- `obj`：触发控件。
- `oper`：64 位操作码，三段——公共段（点击 / 双击 / 右键 / 激活 / 按住 / 拖动 / 投放）、专属段（编辑提交、列表行、结构件关闭等）、搭载段（附加码或数据）。
- `param`：通用参数槽（如标题拖动时的期望坐标）。
- `data`：控件缓冲。

特殊事件名 `CTRL_EVENT_ENTRUST_PARENT` 表示"把本控件的事件委托给父容器"：按父容器 ID 上溯，绑定到父控件的事件；子控件自身不登记处理函数。

处理函数在帧内只做"记录与挂载"，会改动控件对象或缓冲的操作（重装布局、重建文档）交给 `FrameEvent` 的帧间队列，在两窗口渲染结束之后统一执行。这避免了"渲染遍历中改容器"的时序问题。

## 10. 编辑器会话

编辑器的两个窗口都由布局文档驱动：

- **预览窗口**：渲染当前激活布局。所有布局条目共享同一个"唯一预览基座"布局对象；切换激活布局时把该布局的内容重装进基座，而不是为每份布局各留一个布局对象。
- **编辑窗口**：渲染文档中保留名 `KanatUIGenerateEditor` 的布局（外壳布局）的只读快照。外壳快照只在启动时解析一次，会话内固定；界面本身也是 Kanat UI Generate 布局，因此设计器是自举的。
- **内嵌成员**：外壳快照内可以挂"无独立窗口句柄的内嵌窗口"（提示布局），由外壳源同一份解析产物装配，与快照同生命周期。

编辑器逻辑分三件：

| 模块 | 职责 |
| :--- | :--- |
| `editor/GenEditor` | 外壳交互：选中、路径栏同步、提示结论、未保存提醒、事件处理函数 |
| `editor/EditorCommands` | 文档编辑命令：增删布局、改布局名、增删控件、改控件类型、重排控件 |
| `editor/LayoutWriter` | 写方向序列化：中间态 → JSON 文本 / bin 字节，保证"载入后再写出"逐字节一致 |

预览同步：编辑动作改完中间态后请求同步；请求进入帧间队列，在该帧末尾把中间态按编辑情况更新到预览基座（控件数量 / 类型 / 缓冲 / 几何），不做整份文档重装。切换激活布局、新建、载入、增删布局这类结构变化才走整份重装。

选中态是链外视图：`editor/SelectionOverlay` 在预览渲染的每个控件之前回调，按当前选中索引画选中框，不修改布局对象。

## 11. 内存模型

不使用 `new` / `delete`，也不引入智能指针；所有对象由分配器按生命周期分组：

| 分配器 | 用途 |
| :--- | :--- |
| `Arena` | 线性分配器，16 字节对齐，支持整体复位；承载中间态、布局对象、条目数组、字符串 |
| `MemPool` | 小对象池，按固定块回收；承载布局链节点、控件缓冲 |
| `AllocatorHub` | 会话分配器：一次会话一份"池 + 线性"组合，整体释放即会话结束 |

分配器在启动期一次性注入各静态类（`Layout`、`LayoutModel`、`CtrlBuffer`、`ProjCR` 等）；对象释放是显式析构 + 归还，失败路径沿清理链回退。文档结构变化会让中间态换池，旧指针一律失效，因此条目只持有"索引 + 节点指针"，重挂由 `RebindNodes` 统一完成。

## 12. 每帧流程

```text
FrameOnce
  ├─ 无人值守:到点请求退出(KANATUI_GENERATE_AUTOCLOSE_MS)
  ├─ 确保投影配色(跟随系统亮暗;每帧重建采样方向)
  ├─ 编辑窗口段:KanatUIGenerateEditor::Update → RenderBase(外壳快照)→ RenderFlex(内嵌成员)→ IME 口径
  ├─ 预览窗口段:RenderPreviewBase(激活布局 + 点击判定 + 选中叠加件)
  └─ FrameEvent::Drain(本帧挂载的帧间事件)
```

两窗口的段落由 `ImGuiHost` 统一结算：`AcquireWnd` 取下一窗口时结算上一段，帧末兜底结算最后一段。渲染清单顺序即窗口在 ImGui 绘制顺序中的顺序，编辑窗口在前、预览窗口在后。

## 13. 扩展点

- **新增控件类型**：在 `ControlSpec.h` 的类型表加一项 → 决定层次步进 → 在控件库给缓冲容量与绘制分派 → 按需加部件 → 在编辑器类型下拉中可见。
- **替换渲染后端**：另写一套 `RenderApi` / `CtrlApi` / `HostApi` 实现并在启动期注入；布局、几何、事件绑定与编辑器命令不改。
- **新增事件**：在文档写新事件名，在绑定表登记处理函数；复合控件从专属段分配新操作码。
- **新增布局来源**：`Dispatch` 已有"缺省加载链 / 内存缓冲 / 布局模型 / 布局对象数组 / 延迟装配"五种来源的形状；本工程只用前两种。
- **派生新应用**：见 [DERIVE.md](DERIVE.md)。

## 14. 约束与取舍

- **不用虚函数与 RTTI**。解耦一律用函数指针表注入，接口形式是"函数指针类型 + 成员全为该类型的结构体"。
- **唯一预览基座**：多布局共享一个布局对象，用"切换时重装"换内存与渲染一致性；代价是布局对象的控件数随激活布局变化，外部不得缓存控件指针跨布局使用。
- **单文档**：一次只编辑一份文档，切换文档 = 整份载入；没有多标签页。
- **ImGui viewports 未启用**：预览窗口是真实的被编辑文档窗口，与 viewports 的"多视口"语义冲突。
- **交互观感需人工复核**：拖动、悬停、输入法这类交互依赖真实桌面会话，自动化只能覆盖启动与渲染链路。
