# FrameEvent 模块 (src\framework\dispatch\FrameEvent.h)

## 概述

渲染帧间事件队列:纯静态类, 承载"需要等本渲染帧结束之后再执行"的事件。事件回调分两类 —— 帧内触发
(默认, 控件渲染过程中立即调用处理函数)与本类承载的帧间触发:处理函数在自身最前面查 `IsInFrame`,
为真(渲染帧内)时把自身挂到本队列并返回, 为假(帧末排空)时继续执行函数内业务。

队列固定容量、手写环形、先进先出, 无堆分配、无锁。触发方只负责挂载, 排空由宿主主循环在两窗口的渲染帧
都结束之后调用一次 `Drain` 完成。

本模块属 **framework 层**, 依赖 `framework/base/FuncPtr.h`(控件事件回调类型), 不认识控件也不认识布局;
不做时机判定以外的业务语义, 也不重排或去重(去重只认"同一处理函数 + 同一组参数")。

本模块包含以下编程接口:

### 类型

| 类型 | 说明 |
| --- | --- |
| `Entry` | 一枚帧间事件: 处理函数 + 控件对象 + 操作码 + 参数 + 附加数据。 |

### 函数

| 函数 | 说明 |
| --- | --- |
| `Post` | 把一枚事件挂载到帧间队列(相同项合并, 队列满则丢弃并打印诊断)。 |
| `Drain` | 逐枚执行当前全部挂载项并排空队列(防重入)。 |
| `IsInFrame` | 查询当前是否处于渲染帧内(帧间事件的时机判定入口)。 |
| `IsDraining` | 查询帧末排空流程是否活跃。 |

### 常量

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `FRAME_EVENT_CAPACITY` | `64` | 队列槽位总数(环形队列留一格区分空与满 ⇒ 实际可挂载 63 枚)。 |

模块级状态(槽位池、出队游标、入队游标、排空活跃标记)均为文件内静态, 不立条。

## Entry 结构 (FrameEvent)

一枚帧间事件:字段与控件事件回调的四元组一一对应, 排空时按原调用形状回传给处理函数。

### 语法

```cpp
struct Entry
{
    pfnCtrlEvent pfnEvent;
    VOID*        pObj;
    void*        pData;
    uint64_t     qwOper;
    uint64_t     qwParam;
};
```

### 成员

| 成员 | 说明 |
| --- | --- |
| `pfnEvent` | 事件处理函数(与控件事件回调同一签名)。 |
| `pObj` | 触发的控件对象; 挂载时原值保存。 |
| `pData` | 附加数据指针; 挂载时原值保存。 |
| `qwOper` | 操作码。 |
| `qwParam` | 参数。 |

### 注解

字段按大小降序排布, 便于核对对齐; 各字段均为原值拷贝, 本模块不解释也不校验它们。

`pObj` 与 `pData` 是**弱引用**: 从挂载到排空之间隔着本帧剩余的部分渲染, 其间控件对象或缓冲可能已被
释放或改写 ⇒ 处理函数须自行判定其有效性, 不得假定指针仍然有效。本模块不持有它们的生命周期。

## Post 函数 (FrameEvent)

把一枚事件挂载到帧间队列。

### 语法

```cpp
static BOOL Post(
  [in] pfnCtrlEvent pfnEvent,
  [in] VOID*        pObj,
  [in] uint64_t     qwOper,
  [in] uint64_t     qwParam,
  [in] void*        pData
);
```

### 参数

`[in] pfnEvent`

类型: **pfnCtrlEvent**

事件处理函数。为 `NULL` 时直接返回 `FALSE`, 不入队、不打印。

`[in] pObj`

类型: **VOID\***

触发的控件对象, 可为 `NULL`。原值保存, 排空时回传; 生命周期由调用方保证(见 `Entry` 的注解)。

`[in] qwOper`

类型: **uint64_t**

操作码, 原值保存。参与"同一项"的判定。

`[in] qwParam`

类型: **uint64_t**

参数, 原值保存。参与"同一项"的判定。

`[in] pData`

类型: **void\***

附加数据指针, 可为 `NULL`。原值保存, 排空时回传; 生命周期由调用方保证。

### 返回值

类型: **BOOL**

`TRUE` = 已入队, 或已由队列中同一项合并(未重复入队); `FALSE` = 处理函数为 `NULL`, 或队列已满
(此时已打印一条诊断, 本次事件被丢弃)。

### 注解

合并判据 = 五个参数全等(处理函数与四个载荷逐项比较): 队列中已存在同一项时不重复入队, 直接返回 `TRUE`,
因此同一帧内对同一事件的多次挂载只会在帧末执行一次 —— 这是本模块唯一的去重口径, 调用方不必自行判重。

队列采用环形结构并留一格区分空与满 ⇒ 实际可挂载量为 `FRAME_EVENT_CAPACITY - 1`(63 枚)。满时丢弃的是
**新投递**的事件(已在队列中的项不受影响), 诊断经标准输出打印, 每丢弃一枚打印一条。

调用时机: 在控件渲染过程中(即 `IsInFrame` 为真时)由处理函数自身调用。本函数不改排空状态,
也不触发任何执行。

## Drain 函数 (FrameEvent)

逐枚执行当前全部挂载项并排空队列。

### 语法

```cpp
static VOID Drain();
```

### 参数

此函数无参数。

### 返回值

类型: **VOID**

此函数不返回值。

### 注解

调用方 = 宿主主循环, 时机 = 两窗口的渲染帧均结束之后、下一帧开始之前。进入时置"排空活跃"标记, 逐枚
取出并按其原调用形状执行处理函数; 执行期间 `IsInFrame` 为假, 处理函数据此继续执行自身业务(不再重新入队)。

队列为空时安静返回。排空流程已活跃时再次调用会被拒绝并打印一条诊断(防重入), 不重入执行 —— 因此在
处理函数内再次调用 `Drain` 不会造成嵌套执行。

排空收尾: 出队与入队游标复位、全部槽位清零, 下一轮从空队列开始。收尾只在正常走完排空路径时执行;
若某个处理函数在排空过程中重新投递了新事件, 该事件会被本次剩下的循环取到并执行(游标语义为环形顺序)。

本函数不捕获处理函数的异常, 也不保证"排空期间不出现非空队列": 处理函数内投递的新事件同样在本次排空
内执行。

## IsInFrame 函数 (FrameEvent)

查询当前是否处于渲染帧内。

### 语法

```cpp
static BOOL IsInFrame();
```

### 参数

此函数无参数。

### 返回值

类型: **BOOL**

`TRUE` = 渲染帧内(控件渲染过程中触发的调用, 需要帧间处理的应 `Post` 入队并返回);
`FALSE` = 帧末排空执行中(正由 `Drain` 逐枚执行, 处理函数继续执行自身业务)。

### 注解

这是帧间事件的**时机判定入口**: 处理函数的第一个分支就该问它。实现上等价于"排空是否活跃"的反面,
与 `IsDraining` 恒为互为反面, 二者不会同时为真或同时为假。

判定只看排空标记, 不看消息循环与帧的其它阶段: 主循环之外(例如装配期)调用同样返回 `TRUE`。

---

## IsDraining 函数 (FrameEvent)

查询帧末排空流程是否活跃。

### 语法

```cpp
static BOOL IsDraining();
```

### 参数

此函数无参数。

### 返回值

类型: **BOOL**

`TRUE` = 正在逐枚执行帧间事件; `FALSE` = 未在排空(包括从未排空、已排空完毕、以及排空被重入拒绝的情形)。

### 注解

与 `IsInFrame` 互为反面, 语义上等价于对它的取反; 保留两枚取数函数是为了让调用点的意图直读
("我在帧内吗"与"排空在跑吗")。本函数不触发排空, 也不改变状态。

---

## FRAME_EVENT_CAPACITY 常量 (FrameEvent)

帧间事件队列的槽位总数。

### 语法

```cpp
static constexpr DWORD FRAME_EVENT_CAPACITY = 64;
```

### 值

`64`。

### 注解

本值是环形队列的槽位总数, 不是可挂载量:队列留一格区分空与满 ⇒ 实际可挂载 `FRAME_EVENT_CAPACITY - 1`
(63 枚), 满后新投递的事件被丢弃并打印诊断。单槽承载 `Entry`(x64 下 40 字节), 因此整表为固定大小的
进程级静态存储, 不做堆分配、不随事件数增长。
