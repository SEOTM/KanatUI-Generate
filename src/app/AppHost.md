# AppHost 模块 (src\app\AppHost.h)

## 概述

`AppHost` 是进程宿主的唯一入口: 把窗口、渲染设施、消息循环所组成的宿主生命周期收在一处 —— 宿主状态持有、
启动初始化、主循环、帧流程、窗口过程与清理链。层归属为 app 层(宿主 / GUI 外壳层), 与同层的应用会话模块相邻
但职责不同: 本模块是**进程宿主**, 应用会话模块是**文档与布局**的持有者。

五条边界:

1. **不持文档**: 布局、中间态、条目、外壳快照、内嵌成员都归应用会话侧, 本模块只查询。
2. **不画控件**: 绘制归 `framework\render\Render.h` 与 `framework\render\imgui\control\Controls.h`, 本模块只按帧驱动它们。
3. **不做编辑器交互**: 交互归 `editor\GenEditor`, 本模块只驱动其公开入口(初始化 / 帧前联动 / 预览点击记录 /
   未保存改动提醒 / 提示按键结论)。
4. **不持有能力与承载者**: 宿主能力(提示展示器 / 点击处理器 / 两窗口句柄)的持有处是 `app\HostContext`, 文档
   承载者的持有处是应用主类; 本模块只在正确时机把二者写入或转交。
5. **不做环境原语**: 控制台编码、系统亮暗、窗口圆角归 `common\AppEnv`。

命名空间级函数、无实例 ⇒ 进程级单例语义; 宿主状态(两窗口句柄、两套渲染设施与 ImGui context、输入法上下文、
投影配色、无人值守与提示期标志)全部是文件内私有件, 不属公开面。本模块不含线程安全机制: 全部状态在宿主线程
的消息循环内读写。

本模块包含以下编程接口:

### 函数

| 函数 | 说明 |
| --- | --- |
| `Run` | 执行完整宿主生命周期(启动初始化 → 主循环 → 清理链)并返回进程退出码。 |

## Run 函数 (AppHost)

执行完整宿主生命周期并返回进程退出码。

### 语法

```cpp
INT Run();
```

### 参数

此函数无参数。

### 返回值

类型: **INT**

进程退出码: `0` = 正常退出; `1` = 启动期失败(具体文本由本模块经消息框呈现, 外壳快照无效一项除外)。

### 注解

**启动初始化(顺序固定)**: ① 事件绑定表注入 + 预览点击记录器注入 → ② 应用初始化(建立分配器、载入文档、取
外壳快照) → ③ 文档承载者注入 + 命令层会话回调注入 + 命令面回调接线 → ④ 编辑器初始化(注册回调) → ⑤ 按两枚
窗口规格建两窗口(框架注册一枚共用窗口类 + 圆角)并挂业务窗口过程 → ⑥ 两窗口各自初始化 D3D11 → ⑦ 两 ImGui
context + 每个 context 的字体与样式 + Win32 / DX11 后端 → ⑧ 无人值守毫秒数(`GENUI_AUTOCLOSE_MS`)、
同步提示展示器注入、外壳快照有效性校验。

分配器的装配顺序是装配契约, 由第 ② 步内部完成: `AllocatorHub::Init` → `Layout::SetAllocators` /
`LayoutModel::SetAllocators` / `ProjCR::SetAllocators`(同源同批) → 才可 `CreateLayout` / `StateInit`,
顺序不可颠倒。宿主侧的布局创建(外壳快照、文档装配)全部发生在第 ② 步之内 ⇒ 第 ③ 步之后的任何一步都不必也不得
再触碰分配器。

**注入时序(硬约束)**:

| 时机 | 动作 | 约束 |
| --- | --- | --- |
| 最前 | 事件绑定表注入 | 必须早于应用初始化(载入文档时即按事件名解析处理器) |
| 最前 | 预览点击记录器注入 | 同上(首次装配预览基座内容控件时即生效) |
| 应用初始化**成功之后** | 文档承载者注入 | 与上两处相反 —— 承载者必须晚于应用初始化; 且须早于编辑器初始化与编辑器首次解引用承载者 |
| 应用初始化之后 | 命令层会话回调注入 | 命令层不持会话面状态, 改完中间态后经该组回调请求驱动; 与承载者同点 |
| 应用初始化之后 | 命令面回调接线 | 把“追加布局”命令地址交给文档 I/O 模块, 与上一行同点同时机 |
| 应用初始化之后 | 编辑器初始化 | 建窗之前(注册回调) |
| 建窗之后 | 两窗口句柄注册 | 供文件对话框、消息框、内嵌窗口位置基准取用 |
| 提示布局就绪后 | 同步提示展示器注入 | 编辑器弹窗统一入口据此分流; 未注入 ⇒ 回落系统消息框 |
| 清理链内、应用释放**之前** | 承载者置 `NULL` + 会话回调与命令面回调复位 | 必须早于应用释放, 否则承载者随成员块失效 ⇒ 编辑器侧留悬垂指针 |

承载者注入是**唯一“晚于应用初始化”的例外**, 原因在分配点: 承载者按值内嵌在应用侧成员块内, 而成员块要到
应用初始化内部才分配 ⇒ 之前取不到承载者, 提前注入即注入 `NULL`。其余注入的是宿主侧函数与处理部件、不依赖
成员块 ⇒ 一律早于初始化(窗口句柄则在建窗之后)。不得按“注入一律放在初始化之前”的惯例把承载者注入提前。

**窗口几何**: 下列数值均为实现常量: 编辑窗口客户区尺寸取自外壳布局的自动尺寸推导; 快照无效时无描述可依, 按屏
占比兜底(34% 屏宽 × 94% 屏高, 并夹到最小 900 × 1200), 该情形随后由第 ⑧ 步校验判定中止。两类尺寸另有下限夹取
(编辑窗口 200 × 200, 预览窗口 32 × 32), 编辑窗口按屏幕右上角留 24 像素边距摆放。建窗后把外壳布局 `WND` 件的
位置记录落成该建窗位置(初始位置只在此处出现一次)。预览窗口的位置与尺寸就是激活条目的窗口几何 —— 由预览基座
`WND` 件的位置记录承载(装配时取条目 `wndX/wndY`), 两窗口的几何统一由渲染出口在取得渲染目标时经 `AcquireWnd`
结算, 宿主不另算也不直接移动窗口。圆角优先用 DWM 属性, 不可用时回退区域裁剪, 半径取各自参考尺寸的间隔; 区域
裁剪在窗口尺寸变化后须按新尺寸重设, DWM 由系统随尺寸保持。

**主循环**: 消息泵(取消息 → 翻译 → 派发; 收到退出消息即置退出标志) → 无人值守(`GENUI_AUTOCLOSE_MS` 大于 `0`
且到达启动后毫秒数 ⇒ 投递退出消息) → 每帧依次: 确保投影配色 → **编辑帧**(该段取得
渲染目标时按外壳 `WND` 的位置记录结算编辑窗口) → **预览帧**(该段取得渲染目标时按激活布局 `WND`
的位置记录结算预览窗口) → 切回编辑 context → 排空帧间事件队列。

**帧间事件排空点唯一**: 两窗口的渲染帧均已结束、两个 context 都不在帧域内时才排空。帧内处理函数只负责挂载,
真正会改动控件对象与缓冲的业务(重装布局、重建文档一类)在排空时执行; 队列空时该调用无任何影响。

**context 纪律**: 每帧渲染前后显式设置当前 context; 窗口过程进入与返回时保存并还原进入前的 context —— 帧内
窗口消息可能被同步派发, 不还原会让后续渲染落到别的 context 上。两窗口各持一套 D3D 与 ImGui context, 后端数据
按 context 挂载。

**编辑帧**: 交换链被遮挡时整帧跳过(短暂休眠后返回, 与主循环判据一致) → 确保投影配色 → 设当前 context → 取
窗口尺寸变更 → 新帧 → 编辑器帧前联动(选中与缓冲) → 外壳布局渲染(提示展示期间按“窗口级无输入”渲染) →
内嵌(flex)成员逐个渲染(同一 context 同一帧, 位于基座之上) → 输入法状态按是否禁用输入开合 → 渲染并呈现。
同步提示等待期复用同一帧流程(提示布局在编辑窗口内, 等待期间必须持续渲染才能显示与响应点击)。

**同步提示展示器(注入给编辑器的阻塞式入口)**: 按展示参数写标题、正文与两个按钮文本(`NULL` 项保留布局默认
文本; 被覆盖的按钮文本用毕恢复, 免污染下次展示); 按钮宽与横位按文本自适应(按钮宽取“两倍控件高”与“文本宽 ×
字号 + 两倍间隔”的较大者, 每次展示重算故无需恢复); 取消按钮的可见性以临时把控件类型改为不可构建类型实现,
退出前恢复原类型; 每次展示都把提示窗口摆到宿主客户区正中(展示后仍可由人拖动标题栏, 下次展示重新居中); 提示
布局平时非活动(按需显示), 展示前置为活动、用毕复位; **重入守卫**: 已有提示在展示中则直接返回 `FALSE`;
等待循环 = 泵消息 + 渲染编辑帧, 等待期间**不**排空帧间事件队列(避免重入编辑器动作), 收到退出消息视为取消并
把退出消息交还主循环; 提示布局不可用同样返回 `FALSE`, 交调用方回落。

**窗口过程(业务子类化层)**: 框架宿主已收回窗口过程 —— ImGui 后端转发、尺寸登记、显示状态记账、销毁与
`ESC` 退出都在框架内置过程里完成; 本模块在建窗之后把一层业务过程挂到两窗口上(`GetWindowLongPtr` 保存原过程,
`SetWindowLongPtr` 换入业务过程), 业务过程只前置处理两类消息、其余一律经 `CallWindowProc` 原样转交框架过程:
关闭(仅编辑窗口且非提示期 ⇒ 走编辑器的未保存改动提醒入口, 用户取消则**不销毁窗口**; 提示期不受理关闭)、
按键(提示期 `Enter` = 确认 / `ESC` = 取消且**不退出程序**; 非提示期一律透传, `ESC` 退出由框架过程处理)。
ImGui context 的保存与还原在框架过程内部完成, 业务层不触碰 context。

**失败语义**: 初始化类失败(窗口类注册、建窗、D3D 设备、两 context、字体加载、四个后端)置中文错误文本与退出码
`1`, 沿清理链回退, 结束时经消息框呈现。**外壳快照无效不置错误文本**: 诊断走标准输出并直接退出码 `1`。字体
全部加载失败时退默认字体 + 消息框警告, **不阻断**启动。

**清理链**: 与启动顺序**逆序**的分级回退 —— 输入法上下文释放 → 两 ImGui context(先预览后编辑) → 两套 D3D →
两窗口销毁 → 注销共用窗口类名 → 投影配色释放 → 文档承载者复位与会话 / 命令面回调复位 → 应用释放。
投影配色必须先于应用释放: 其轴位置表要在分配器解绑之前归还小对象池。早失败只回退已建立的部分(分级标签),
正常退出则全链走完。

## 要求

| 要求 | 值 |
| --- | --- |
| 标头 | `app/AppHost.h`(`src\app\AppHost.h`) |
| 实现 | `src\app\AppHost.cpp` |
| 命名空间 | `AppHost`(命名空间级函数, 无实例) |
| 依赖 | 工程内: `Application`、`PreviewSession`、`FlexHost`、`DocumentIO`、`HostContext`、`GenUIEditor`、`EditorCommands`、`UIEventHandler`、`SelectionOverlay`、`Render`、`Controls`、`ControlSpec`、`CtrlBuffer`、`TextWidth`、`ProjCR`、`AppEnv`、`D3D11Manager`、`FrameEvent`; 系统: `d3d11`、`dwmapi`、`imm32`(输入法上下文)与 ImGui 的 Win32 / DX11 后端 |

| 线程安全 | 否(全部宿主状态在宿主线程的消息循环内读写; 帧内消息可能被同步派发, 故 context 逐次保存与还原) |
